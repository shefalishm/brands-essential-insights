## Before development

Create a complete URL inventory using the sitemap, analytics, search performance, backlink data and a crawl. Label pages to keep, improve, consolidate or retire. Record titles, descriptions, headings, canonical tags, index directives and structured data for pages that matter.

Map every changed URL to the closest new destination. Preserve high-value content and internal-link relationships unless research supports a deliberate change.

## Before launch

- Crawl the staging site while keeping it unavailable to public indexing.
- Confirm each page has one intended canonical URL.
- Test redirect mappings and eliminate chains.
- Validate mobile layouts, forms, analytics and consent.
- Check robots directives and generate the production sitemap.
- Review status codes, metadata, headings and structured data.
- Establish performance and ranking baselines.

## On launch day

Remove staging restrictions only from production. Deploy server-side redirects, verify analytics, test priority journeys and inspect a representative sample of old and new URLs. Submit the sitemap through the relevant webmaster tools after the live version is confirmed.

## After launch

Monitor crawl errors, excluded pages, indexed URLs, organic landing pages, conversions and server logs where available. Fix systemic patterns first: a faulty template or redirect rule can affect hundreds of pages.

Avoid reacting to every daily fluctuation. Compare meaningful periods and annotate the launch so performance changes have context.

## Make migration one workstream

SEO cannot be a final-day checklist owned by one specialist. Strategy, copy, design and development decisions all affect what search systems can find and what users experience. Put migration requirements into the build plan from the beginning.
